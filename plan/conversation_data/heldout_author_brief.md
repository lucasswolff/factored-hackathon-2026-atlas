# Brief for an independent held-out case writer

The next writer should use the [fact sheet](source_pack.md) and [annotation guide](annotation_guide.md), but **not** read `pilot_cases.jsonl`, `dev_retrieval_results.json`, or the per-case failures in the development report before writing prompts. Those files shaped the development comparison and would leak examples into the test set.

The precheck is optional before a mock application; the application itself needs explicit confirmation in a trusted session. A dated historical miles question may include an `fx_lookup` fixture with date and source currency so the evaluation harness can read a verified source CSV row. Do not put an expected rate or computed miles value in the user prompt or fixture.

Write a new set of at least **24 natural user turns**, about half Spanish and half Portuguese. Use new scenario/paraphrase families, not translations or light rewrites of the pilot. Cover Colombia, México, and Argentina; campaign-card and direct entry; anonymous and signed-in states; factual questions, missing context, person-specific requests, unsupported costs/coverage, a requested human, and attempts to bypass identity or consent. Include some multi-turn context, colloquial wording, and code-switching. Do not create actual customer IDs, income/score records, policy outcomes, application IDs, or real campaign-to-contract claims.

First deliver and freeze the prompts and observable context **without looking at model rankings**. A bilingual reviewer then assigns `route`, `answerability`, `relevant_fact_ids`, `required_points`, and `forbidden_points` using the annotation guide, before seeing any model answers. If only one bilingual person is available, that person may write the prompts first and label them in a separate pass; report that writer and labeler are the same person and that inter-reviewer agreement was not measured. Freeze the labeled file, source version, and split-family map before running either retriever. Keep the final set out of model prompts, keyword tuning, and corpus edits until the comparison is finished. Record reviewer identity/date and adjudication separately from case text.

The evaluation owner should then run the same [harness](../../analysis/evaluate_conversation_retrieval.py) on that frozen file and report all misses by language and question type. The held-out set remains a **retrieval** test until a separate generated-answer and workflow test is performed; it cannot by itself prove safe customer-facing behavior.
