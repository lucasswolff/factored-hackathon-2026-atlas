# Credit-card advisor work plan

**Status: local browser demo under test, 2026-09-30.** The earlier synthetic prototype was removed. The [advisor](../advisor/README.md) supports campaign and direct starts, public product questions, 10 allowlisted demo personas, profile-based recommendations, a [simulated precheck](demo_credit_policy.md), and chat-confirmed mock applications. Browser fixture selection permits profile use; precheck and application confirmation are separate. The [conversation contract](conversation_contract.md) records the remaining gates. The [MVP requirements](../docs/mvp_requirements.md), [draft four-card catalog](../docs/card_catalog_draft.md), and [training-data assessment](../docs/training_data_assessment.md) define the direction. Local CSVs and Snowflake landing tables came from the same AWS source. Never treat demo-created offers, clicks, suggestions, or applications as historical bank events.

| Step | Deliverable | Completion check |
| --- | --- | --- |
| **1. Campaign cards and mapping — initial audit done** | [Campaign shortlist and explicit source-to-demo-offer mapping](campaign_cards.md), one visible card per named offer. | Every displayed card has a real source campaign ID, a matching source audience where possible, a labeled team-created offer mapping, and a documented country/status limitation. No historical clicked conversation is selected. |
| **2. Four country-specific offers — draft in progress** | [Country-variant offer terms](card_offer_terms.md) for Campus, Horizon, Rewards, and Summit in Colombia, México, and Argentina. | Financial terms, spend-based fee-waiver rules, benefit limits, exclusions, active dates, and disclosures are explicit; Campus is student-only and Rewards has fewer travel benefits than Summit. Core benefits match across countries; fees and disclosures are localized. Unknown terms are not invented. |
| **3. Recommendation and precheck policy** | Separate, versioned rules for suggestions and simulated prequalification. | Uses country-specific local-currency income bands, credit score, existing products, and segment; only a selected, server-bound demo fixture receives suggestions. Self-reported income is not silently substituted. No AI approval. |
| **4. Conversation entry contract** | Spanish/Portuguese opening messages and state transitions for campaign-card and direct starts. | A campaign start knows its selected demo offer and source campaign; a direct start has no campaign. Both lead to demo-customer selection before profile-based answers. |
| **5. Conversation data and evaluation — AI-only checks done** | [Versioned fact sheet, annotation guide, 24 draft cases, keyword/E5 comparison, Sonnet answer check, and AI-authored challenge](conversation_data/README.md). Blind human-review packets remain available, but the user requested an AI-only pass first. | Tests include free-form questions, ambiguous/unsupported requests, missing fields, student-only requests, unauthorized access, and both entry paths. Transcript examples inform tone only. AI-authored/AI-judged counts are not independent held-out quality claims. |
| **6. Build and demo** | UI, trusted test sessions, controlled data tools, conversation layer, simulated policy, mock application, verified human handoff, and measured evaluation. | Meets the [MVP acceptance criteria](../docs/mvp_requirements.md#acceptance-criteria-and-evaluation). A/B testing remains later work. |

Step 1 is a **planning shortlist**, not a claim that historical campaigns advertised these four cards. The source rows only identify `Tarjeta Crédito`; the named offers and mapping are team-created. The current browser journey uses draft offer and policy versions. Final terms, independent bilingual review, verified handoff, and real identity remain open before treating it as a complete MVP.
